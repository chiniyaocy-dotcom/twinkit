# 人格包格式（twinkit-persona/1）

人格包是一个目录，里面全是普通 Markdown。TwinKit 只依赖少量约定：`#` 标题、标题下面的 `- 键：值` 元信息、`##` 小节。

```text
persona/
├── persona.md          必需
├── profile.md          建议
├── methods/*.md        建议 ≥ 3 个
├── decisions/*.md      建议 ≥ 3 个
├── taste/*.md          建议 ≥ 1 个
└── voice/*.md          建议 ≥ 1 个
```

- 以 `_` 或 `.` 开头的文件、以及 `README.md` 不会被读取（可以放草稿）。
- HTML 注释 `<!-- … -->` 会被忽略（模板里的填写说明就写在注释里）。
- 代码块里的 `#` 不会被当成标题。
- 中文冒号 `：` 和英文冒号 `:` 都可以。

## persona.md

```markdown
# 周屿 · 数字分身

- 姓名：周屿
- 标识：zhou-yu
- 角色：连锁茶饮品牌运营总监
- 一句话：做了 11 年门店运营……
- 语言：中文
- 快照日期：2026-09-30

## 身份
## 决策原则
## 禁区
## 质量标准
## 交付物
## 长期目标
```

### 元信息

| 键（任选一个写法） | 含义 |
|---|---|
| `姓名` / `名字` / `name` | 名字。没写时取 `#` 标题里 `·` 前面的部分 |
| `标识` / `handle` / `slug` | 英文标识，用于服务名（`twinkit-<标识>`）和客户端里的名字；只保留小写字母、数字和 `-` |
| `角色` / `职位` / `role` | 角色，会写进“角色锁定”和对照实验里的“通用角色”条件 |
| `一句话` / `简介` / `tagline` | 一句话介绍 |
| `语言` / `language` | 说明用，目前不影响输出 |
| `快照日期` / `更新日期` / `snapshot` | 人格包的整理日期，会显示在简报和 `/health` 里 |
| `披露` / `disclosure` | 自定义披露语，**必须**说明这是 AI 数字分身。不写则使用默认披露语 |
| `虚构` / `fictional` | `是` 表示虚构人物（示例用），默认披露语会相应改变 |

只有上表里的键会被当作元信息；其他 `- 键：值` 行会留在正文里。

### 小节

| 小节（任选一个写法） | 内容 | 必需 |
|---|---|---|
| `身份` / `关于我` / `Identity` / `About` | 2–4 句话 | 建议 |
| `决策原则` / `原则` / `Principles` | 列表，每条一个原则 | ✅ |
| `禁区` / `红线` / `Prohibitions` / `Never` | 列表。**用引号括起来的词**（“赋能”「抓手」"synergy"）会被 `review` 当作禁用词 | ✅ |
| `质量标准` / `标准` / `Quality bar` | 列表，会变成简报里的自检清单 | ✅ |
| `交付物` / `Deliverables` | 见下 | ✅ |
| `长期目标` / `职业规划` / `Goals` | 自由文本 | 可选 |

其他任何 `##` 小节都会原样出现在档案（`get_profile`）里。

### 交付物

每种交付物一个 `###` 标题，括号里写别名，`默认` 表示判断不出类型时使用；下面列出它的章节，可以用“名称：说明”。

```markdown
## 交付物
### 方案（proposal, plan, 默认）
- 结论：要做什么、要多少资源、预期结果
- 背景与目标
- 风险与预案

### 周报（weekly report, 周汇报）
结论 / 核心数据 / 问题与原因 / 下周动作
```

- 别名用 `,`、`，`、`、` 分隔。
- 章节可以写成列表，也可以写成一行用 ` / ` 或 `→` 分隔。
- `work_brief` 会根据参数 `deliverable` 或任务文字里出现的名称/别名选择结构；`review` 会检查草稿是否覆盖了每个章节（章节名里的“与/和/、”会被拆开，命中其中一部分就算覆盖）。
- 第一个章节叫“结论 / 摘要 / Summary”时，`review` 还会检查结论是否放在了最前面。

## 卡片（methods / decisions / taste / voice）

四类卡片的格式相同：

```markdown
# 卡片标题
- 关键词：价格战、降价、9.9、竞品
- 适用：……        （methods 常用）
- 日期：2025-06    （decisions 常用）
- 场景：……        （taste / voice 常用）
- 默认：是         （voice：没有匹配时使用的语气）

## 任意小节
内容……
```

- **关键词决定了这张卡什么时候被调出**。写别人描述这类任务时会用的各种说法（“开店”“新店”“开业”都写上）。
- 匹配规则：任务文字里出现关键词得分最高；其次是标题和正文的词语重合（越少见的词权重越高）。`work_brief` 每次最多调出 3 个方法、2 个决策、2 个品味和 1 个语气。
- 小节名随意，常用的结构：
  - methods：核心思路 / 步骤 / 检查点 / 常见坑
  - decisions：情境 / 选项 / 选择 / 理由 / 结果 / 复盘
  - taste：好的样子 / 不好的样子 / 为什么
  - voice：特点 / 示例 / 避免（“避免”里用引号括起来的词会被当作禁用词）

## profile.md

公开档案，`get_profile` 和 `twin://profile` 会原样展示其中的小节。常用：经历、擅长、不擅长 / 会交给别人、合作方式。

## 检查规则（npm run validate）

| 级别 | 规则 |
|---|---|
| 错误 | 缺 `persona.md`；缺名字；缺决策原则 / 禁区 / 质量标准 / 交付物；交付物没有章节；残留 `{{…}}` 占位符（注释里的不算）；披露语没说明是 AI；卡片为空；疑似手机号、身份证号、密钥 |
| 提醒 | 缺角色 / 快照日期 / 身份；原则少于 3 条；方法或决策少于 3 个；卡片没有关键词；疑似邮箱、座机、银行卡号；人格包超过 800 KB |

`--strict` 会把提醒也当作错误（CI 和 Gallery 用）。

## 构建产物

`npm run build` 生成：

- `dist/worker.js`：单文件 Worker，人格包以 JSON 形式内嵌。
- `dist/persona.json`：解析结果（格式 `twinkit-persona/1`），可以用来检查解析是否符合预期。
- `dist/prompt.md`：完整提示词包。
