# 安全、授权与边界

数字分身离“冒充”只有一步。TwinKit 的默认设置和规则都朝着一个方向：**它是帮本人干活的工具，不是本人。**

## 1. 永远表明自己是 AI

- 每个人格包都有披露语（不写就用默认的），出现在工作简报、MCP 服务说明、落地页和提示词包里。
- 简报和提示词包都要求：被问到是不是本人时，必须如实说明自己是 AI 数字分身。
- `validate` 会拒绝没有说明“AI / 分身”的自定义披露语。
- 如果你把分身起草的内容发给别人，是否告知对方由你决定，但责任在你。

## 2. 只为自己建分身

- 只用**你自己的**工作方式建分身。为别人（同事、前任上司、公众人物……）建分身，必须有对方明确的书面授权，并由对方确认内容。
- Gallery 只收录本人提交的本人分身（`consent.owner_is_subject: true`），虚构人物只能作为演示条目。
- 发现有人冒用你的身份建分身，请开 issue 或直接联系维护者，我们会尽快下架相关条目。

## 3. 不越权

- 所有工具都是**只读**的：分身只提供“怎么做”的简报和检查，不会发消息、付款、改文件或调用其他系统。
- 简报明确要求：输出是工作稿，不能以本人名义对外承诺、签署、审批、付款或发布。
- `review` 会把“我保证”“已批准”“代表公司”等表述标为“必须修改”。
- 路线图上的“代办动作”（例如起草后直接发送）会采用分级权限：默认只读；起草需要显式开启；任何对外动作都必须由本人逐次确认。

## 4. 隐私

- 人格包里不要放：身份证号、手机号、住址、客户名单、他人隐私、公司机密、密钥。`npm run validate` 会扫描常见的隐私和密钥格式，但扫描不能代替你自己通读。
- **公开模式下，任何人都能通过工具读到人格包的全部内容。** 敏感内容请用私有模式（令牌），并把仓库设为 Private。
- 分身运行在你自己的 Cloudflare 账号里。TwinKit 代码不记录请求内容；可选的统计只记录“哪天有过工具调用”。Cloudflare 的请求日志（`observability`）包含请求元数据但不含请求体，不需要可以在 `wrangler.toml` 里关闭。
- 你使用的 AI 客户端如何处理对话内容，取决于该客户端自己的政策。

## 5. 提示注入

工具返回的文字会进入 AI 的上下文。人格包是你自己写的，所以风险主要在于**接入别人的分身**：一个恶意的人格包可以在“方法”里藏指令。只接入你信任的分身；Gallery 会审核条目，但不能保证第三方内容的安全。

## 6. 滥用防护

- 公开分身默认按 IP 限流（每 60 秒 60 次）。
- 请求体上限 1 MB，单个参数有长度限制。
- 请不要把分身接入自动化脚本去批量刷调用；这既浪费免费额度，也会污染“持续使用”的统计。

## 报告问题

安全问题请不要公开发 issue，请在 GitHub 上使用 “Report a vulnerability”（Security 标签页）私下报告。
